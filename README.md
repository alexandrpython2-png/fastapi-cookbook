# Кулинарная книга

Асинхронный API кулинарной книги на FastAPI и асинхронной SQLAlchemy с базой SQLite (драйвер aiosqlite).

```shell
pip install -r requirements.txt
uvicorn cookbook.main:app --reload
```

Документация открывается по адресу http://127.0.0.1:8000/docs: там описаны все запросы, поля и ошибки, и любой
запрос можно отправить кнопкой «Try it out». Та же документация в другом оформлении — `/redoc`, схема OpenAPI для
генераторов клиентов — `/openapi.json`.

База создаётся при первом запуске в файле `cookbook.db`. Другую базу можно задать переменной окружения
`DATABASE_URL`, например `sqlite+aiosqlite:///./other.db`.

## Запросы

| Запрос | Экран | Что возвращает |
|---|---|---|
| `GET /recipes` | таблица рецептов | `id`, название, количество просмотров и время готовки всех рецептов, сначала самые популярные |
| `GET /recipes/{recipe_id}` | рецепт | название, время готовки, ингредиенты и описание; увеличивает количество просмотров на 1 |
| `POST /recipes` | добавление рецепта | созданный рецепт с его `id`, код ответа 201 |

Популярность — количество просмотров, то есть сколько раз открыли детальную информацию о рецепте. Рецепты с равным
количеством просмотров отсортированы по времени готовки, сначала самые быстрые.

## Как устроено

| Файл | Что в нём |
|---|---|
| [cookbook/main.py](cookbook/main.py) | создание приложения, описание API для документации, создание таблиц при запуске |
| [cookbook/routes.py](cookbook/routes.py) | три запроса |
| [cookbook/schemas.py](cookbook/schemas.py) | схемы запросов и ответов с описаниями полей и проверками |
| [cookbook/models.py](cookbook/models.py) | таблицы `recipes` и `ingredients` |
| [cookbook/database.py](cookbook/database.py) | адрес базы и сессия на каждый запрос |

- Каждый запрос получает свою сессию базы данных через зависимость `get_session`. Одну сессию нельзя
  использовать из нескольких запросов одновременно.
- Количество просмотров увеличивает сама база одним запросом `UPDATE recipes SET views = views + 1`. Если бы
  приложение читало значение и записывало его обратно, одновременные просмотры терялись бы.
- Ингредиенты хранятся в отдельной таблице и возвращаются в том порядке, в котором их добавили.

## Тесты и линтеры

```shell
pip install -r requirements-dev.txt
pytest --cov          # тесты и покрытие кода
flake8 .              # стиль и типичные ошибки
isort --check-only .  # порядок импортов
black --check .       # форматирование
mypy .                # типы в строгом режиме
bandit -r cookbook    # типичные уязвимости
```

Тесты в [tests/test_recipes.py](tests/test_recipes.py) запускают приложение на временной базе и проверяют все
запросы, сортировку, подсчёт просмотров, ответы на неверные данные, одновременные просмотры и документацию.
Покрытие кода тестами должно быть не меньше 95%, иначе `pytest --cov` завершается с ошибкой.

Настройки black, isort, mypy, pytest и coverage лежат в [pyproject.toml](pyproject.toml), настройки flake8 — в
[.flake8](.flake8): flake8 не читает pyproject.toml.

- **black и flake8.** По умолчанию black переносит строки длиннее 88 символов, а flake8 требует не больше 79.
  Поэтому у обоих задана одна длина — 120. Кроме того, black оформляет срезы как `items[start : end]` и записывает
  заглушки `def f(): ...` в одну строку, а flake8 считает это ошибками E203, E701 и E704. Эти три правила выключены.
- **isort и black.** С настройками по умолчанию isort переносит длинные импорты иначе, чем black. Профиль
  `profile = "black"` оформляет импорты так же, как black.
- **mypy** работает в строгом режиме (`strict = true`) с плагином pydantic, который проверяет создание схем.
